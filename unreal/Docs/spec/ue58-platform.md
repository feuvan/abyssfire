# Port Spec — Unreal Engine 5.8 Target Platform & Engine Integration (macOS · Windows · Android · iOS)

Area owner: platform / engine integration. Web source of truth: branch `claude/unreal-rebuild`. Only the web
**platform layer** is ported by this document (`src/config.ts`, `src/main.ts`, `src/rendering/*.ts`,
`src/systems/MobileShell.ts`, `src/systems/MobileControlsSystem.ts:16-44`, `src/systems/SaveSystem.ts`,
`src/i18n/index.ts`, `src/ui/UiKit.ts:19-20`, `src/systems/audio/AudioManager.ts`); every gameplay rule lives in the
sibling specs.
Target: portable C++20 core **`AbyssCore`** (no UE types, no exceptions, no RTTI, unit-tested with CMake) + thin UE 5.8
C++ module **`Abyssfire`** (render / input / UI), art generated by Blender Python, UE content built by UE editor Python.
True 3D, fixed oblique camera (`world-map-nav.md` §8: yaw −135°, pitch −30°, horizontal FOV 30°, 100 uu = 1 tile).

Research date **2026-10-08**. The research sandbox could not fetch `dev.epicgames.com` / the Epic forums directly
(egress blocked), so facts below come from web-search extracts of those pages. Evidence tags:

| Tag | Meaning |
|---|---|
| **[Epic]** | Epic release notes / requirements pages / roadmap (as quoted by search results, 2026-10-08) |
| **[Forum]** | Epic forum or community report (single source, not confirmed by Epic) |
| **[API]** | Long-stable UE 5.x API known from engine source; signature must be re-checked against the 5.8.3 headers (§17) |
| **[Decision]** | Recommendation of this spec (the default unless an open question, §18, is resolved otherwise) |
| **[Verify]** | Must be confirmed on the first UE 5.8.3 install — every one is listed in the checklist §17 |

"**render-only**" marks web artefacts (Phaser / DOM / browser) together with their UE equivalent.

  Do not chase UE6 for milestone 1; keep engine-touching code thin so a UE6 port is mechanical.

### 3.2 C++ standard **[Epic]**

UE 5.8 compiles the engine as **C++20** and requires C++20 to build (Epic C++ coding standard page). Project modules
default to C++20 under current build settings. **[Decision]** set `CppStandard = CppStandardVersion.Cpp20` explicitly
in both modules (not `Latest`: C++23 library support differs between MSVC, Apple libc++ and NDK libc++).

### 3.3 Language and library rules for `AbyssCore` (portable C++20 under four toolchains)

The core is compiled by: MSVC 14.38–14.50 (STL), Apple clang from Xcode 26 (libc++, deployment iOS 17 / macOS 14.5),
NDK r27c clang (LLVM 18, libc++ 18, linked statically by UE), GCC/Clang on Linux (CMake tests).

| Area | Rule | Why |
|---|---|---|
| Exceptions | No `try/throw/catch`; never call throwing APIs: `vector::at`, `optional::value`, `std::get<T>(variant)` (use `std::get_if`), `std::stoi/stod`, `std::regex`, `std::filesystem`, `std::bad_alloc` handling | UE builds the module with `bEnableExceptions=false`; a throw would `std::terminate` |
| RTTI | No `dynamic_cast`, `typeid`, `std::any`, `std::function::target`; use enum tags / `std::variant` / visitors | `bUseRTTI=false` (`/GR-`, `-fno-rtti`) |
| I/O | No `<iostream>`, `<fstream>`, `fopen`: the core receives **bytes** (`std::string_view`) and returns bytes | Packaged files live inside the pak; only UE's `IPlatformFile` can read them (§10) |
| Threads | No `<thread>`, `<future>`, `<execution>`, `std::jthread`; the core is single-threaded, called on the game thread | Mobile thread budgets; libc++ 18 gaps |
| RNG | Own PRNG (spec'd per area); **never** `<random>` distributions (`uniform_int_distribution` etc. give different sequences on MSVC/libc++/libstdc++), `rand()`, `std::random_device` | Cross-platform reproducibility, golden tests |
| Hashing / ordering | Never iterate `std::unordered_map/set` where order influences gameplay, RNG draws or saved output; JS `Map`/object iteration is **insertion order** → use `std::vector` of pairs or an insertion-ordered map; `std::hash` values never persisted | STL implementations differ |
| Sorting | JS `Array.prototype.sort` is **stable** → port with `std::stable_sort` (or `std::ranges::stable_sort`) and the same comparator | `std::sort` order of equal elements differs per STL |
| Floating point | Put `#pragma STDC FP_CONTRACT OFF` (+ `#pragma clang fp contract(off)` under `__clang__`) in a core-wide header included first by every `.cpp`; CMake adds `-ffp-contract=off`. No `-ffast-math`. The pragmas do not survive `-ffp-contract=fast` / `-ffast-math` / `/fp:fast`, so both Build.cs files set `FPSemantics = FPSemanticsMode.Precise` (the public headers' inline math is compiled in the game module too) and `Platform.h` `#error`s in a core TU built with fast-math; MSVC also gets `#pragma float_control(precise, on)`. Use `std::floor(x + 0.5)` for JS `Math.round` | Clang ≥ 14 contracts `a*b+c` into FMA by default on arm64 (Mac/iOS/Android) while MSVC x64 and JS do not → `.5` rounding boundaries could flip |
| Number parsing | Do not use `strtod`/`atof` (locale-dependent) or floating `std::from_chars` (absent in NDK r27 libc++). Integers: `std::from_chars` OK. Floats: in-house decimal parser (digits/fraction/exponent → double) in the JSON reader | Portability |
| Formatting | Avoid `<format>` and iostreams in hot paths; i18n templates use the core's own `{name}` substitution | size, availability |
| Text | All strings UTF-8 `std::string`; **no non-ASCII literals in C++ sources** (all player-facing text is in JSON); never use `u8"..."` (C++20 makes it `char8_t`) | MSVC source charset, C++20 `char8_t` |
| Integer types | `<cstdint>` fixed widths; never `long` (32-bit on Windows, 64 elsewhere) or `wchar_t` | ABI differences |
| Statics | No namespace-scope objects with non-trivial constructors; use function-local statics | static-init order, mobile startup |
| Macro collisions | Core headers are included next to UE headers in the `Abyssfire` module: never name anything `check`, `verify`, `ensure`, `checkf`, `TEXT`, `PI`, `SMALL_NUMBER`, `KINDA_SMALL_NUMBER`, `BIG_NUMBER`, `INDEX_NONE`, `IN`, `OUT`, `TRUE`, `FALSE`, `ERROR`, `DELTA`, `UNLIKELY`, `LIKELY`, `FORCEINLINE`, `min`/`max` macros; prefer `kPascalCase` constants inside `namespace abyss` over `UPPER_SNAKE`; public headers write `(std::min)(a, b)` / `(std::numeric_limits<T>::max)()`. `CoreTests/shim/MacroShim.cpp` compiles every public header after these (and more Windows / UE / Apple) macros | UE / Windows macros |
| Warnings | Must compile clean with `-Wall -Wextra -Wshadow -Wundef -Werror -Wno-unused-parameter` (clang/gcc) and `/W4 /WX /we4668` (MSVC) in CMake | UE treats shadowing (C4456–C4459, `-Wshadow`) and undefined-identifier-in-`#if` as errors on several platforms |
| Allowed C++20 | concepts, designated initialisers, `<=>`, `consteval/constexpr`, `using enum`, `[[likely]]`, `<span>`, `<bit>` (`bit_cast`), `<numbers>`, `<concepts>`, `std::ranges` algorithms, `<source_location>`, `<charconv>` (integers), `std::variant` + `std::visit`/`get_if`, `std::optional` (`*`/`has_value`) | supported by all four toolchains |
| Forbidden C++20 | modules, coroutines, `std::format` (optional later), `<stop_token>`, `<syncstream>`, `<chrono>` calendars/time zones | toolchain gaps |
| Assertions / logging | core macro `ABYSS_ASSERT(cond, msg)` → user-installable handler; log through a callback the UE module routes to `UE_LOG` | no UE dependency |

Sources disagree on the 5.8 enum value (`BuildSettingsVersion.V5` / `V6` / `V7`, `EngineIncludeOrderVersion.Unreal5_8`)

## 6. Rendering

### 6.1 Desktop (Mac Metal SM5, Windows D3D12 SM5)

* **Deferred** renderer, `r.ForwardShading=False`. Reason: 5.8.0/5.8.1 render **no meshes with forward + MSAA on
  Apple M1/M2** **[Forum]**; Mac is the primary platform. Re-test on 5.8.3; if fixed, desktop forward + MSAA becomes an
  option for a crisper outline (Q2).
* AA: **TSR** (`r.AntiAliasingMethod=4`) on balanced/high; **FXAA** (`1`) on low. Thin hull outlines (2–4 px) are
  stable under TSR; watch for ghosting on fast dodge afterimages (Q2).
* Off: Lumen (`r.DynamicGlobalIlluminationMethod=0`), reflections (`r.ReflectionMethod=0`), VSM, Nanite, ray
  tracing, mesh distance fields, static lighting, sky atmosphere, auto exposure, motion blur, AO. All lighting is the
  zone's movable directional light + per-material ambient (§6.5).
* Shadows: movable directional light with **CSM**, `DynamicShadowDistanceMovableLight` ≈ 3500 cm (the parity camera
  sees ≈ 16 × 9 m), 2 cascades (balanced) / 3 (high), `r.Shadow.MaxCSMResolution` 2048. Characters are Unlit but still
  **cast** shadows (`bCastDynamicShadow` is independent of the shading model) **[API]**; only lit materials (ground,
  optionally props) **receive** them (§6.5).

### 6.2 Mobile (Android Vulkan / GLES 3.2, iOS Metal)

* **[Decision] Mobile forward** (`r.Mobile.ShadingPath=0`) even though 5.8 made multi-pass deferred the default
  **[Epic]**. Rationale: almost every material is Unlit (§6.4) so deferred buys nothing; forward allows **MSAA 4×**
  (deferred does not) which keeps hull outlines crisp; lower bandwidth/memory on tile GPUs; widest device support
  (Epic: deferred "requires relatively higher-end mobile hardware"); avoids the reported 5.8 mobile-deferred
  regressions **[Forum]**. Cost: no SSAO/SSR/contact shadows (unused anyway).
* `r.MobileHDR=True` — required for bloom, tonemapper and post-process materials on mobile. A Mali-G76 crash with
  MobileHDR on 5.8.0 is reported **[Forum]**; keep it on the device test list.
* Feature constraints on mobile forward **[Epic]**: no Lumen (experimental on high-end Android only, never iOS), no
  Nanite, no VSM, movable point-light shadows only on D3D (so **none** on Vulkan/Metal), limited dynamic local lights,
  CSM from a movable directional light works when there is no precomputed lighting (`r.AllowStaticLighting=False`),
  d-buffer decals supported since 5.5.
* Shadows per tier: **low = blob only** (`art-inventory-ch1.md` §1.4 contact shadows), **balanced = blob + 1 CSM
  cascade 1024²**, **high = blob + 2 cascades 2048²** (`r.Shadow.CSM.MaxMobileCascades`, `r.Shadow.MaxCSMResolution`
  per device profile).
* Many small lights (torches, spell glows, loot pools — web `LightingSystem` caps 8/16/32 by tier,
  `src/rendering/RenderQuality.ts:13-24`) are **fake lights**: additive unlit "light pool" quads/decals and emissive
  bloom, not `UPointLightComponent`s. Desktop may add ≤ 4 real point lights for hero-adjacent effects.

### 6.3 Mac / Windows / mobile visual parity

Preview mobile looks on the Mac with **Settings → Preview Rendering Level → Android Vulkan / iOS** (5.8 re-enabled mobile
and SM5 preview platforms when running the SM6 Metal RHI) **[Epic]**. Every material must compile for SM5 and ES3.1/Metal
mobile feature levels; keep Custom-node HLSL to SM5 intrinsics (no wave ops, no SM6-only types).

### 6.4 Toon shading — options and decision

|---|---|---|---|---|
| **A. Unlit material + custom lighting** (N·L from a Material Parameter Collection sun vector, 3-band ramp, rim, ambient in shader) | yes (cheapest possible) | no (use blob shadows; ground is lit, see B') | yes (`MaterialEditingLibrary` + Custom node) | **[Decision] characters, NPCs, props, foliage** — matches `art-inventory-ch1.md` §1.2 `M_AF_Toon` |

Material Parameter Collection **`MPC_AF_Lighting`** (written by C++ every frame from the zone lighting data, the same
values that drive the directional light):

| Parameter | Type | Meaning |
|---|---|---|
| `SunDir` | vector (xyz) | unit vector **towards** the sun in world space (`-DirectionalLight->GetForwardVector()`) |
| `SunColor` | vector (rgb, linear) | sun colour × intensity scale (1.0 = neutral) |
| `Ambient` | vector (rgb, linear) | ambient / sky fill |
| `RimColor` | vector | rim tint (`#FFECC8` × 0.55, `art-inventory-ch1.md` §1.4) |
| `CameraTanHalfFovY` | scalar | for screen-constant outline/WPO math |
| `TimeSec` | scalar | wind sway, pulses (independent of game pause if desired) |

Custom-node HLSL for option A (inputs `N` = `PixelNormalWS`, `L` = `SunDir`, `Base` = base colour **as sRGB-encoded
0..1 values** (sample the palette with `SamplerType = Color` and convert back, or keep a `Linear` palette texture
holding sRGB values), `ShadowAmt`, `LightAmt`, `TShade` 0.42, `TLight` 0.86, `W` 0.02):

```hlsl
float ndl = dot(normalize(N), normalize(L)) * 0.5 + 0.5;            // half-Lambert
float3 shade = lerp(lerp(Base, float3(30,20,60)/255.0, 0.35), 0.0.xxx, ShadowAmt);
float3 light = lerp(Base, float3(255,244,214)/255.0, LightAmt);
float sBase  = smoothstep(TShade - W, TShade + W, ndl);              // shade -> base
float sLight = smoothstep(TLight - W, TLight + W, ndl);              // base -> light
float3 c = lerp(lerp(shade, Base, sBase), light, sLight);            // sRGB-space tone (web tone()/cel())
// sRGB -> linear for the Emissive output
float3 lo = c / 12.92;
float3 hi = pow((c + 0.055) / 1.055, 2.4);
return lerp(lo, hi, step(0.04045, c));
```

Rim, grounding gradient, hit flash / telegraph / status tints (`art-inventory-ch1.md` §1.4, §1.8) are added after the
Custom node with ordinary expression nodes. Material settings: `MaterialDomain=Surface`, `ShadingModel=Unlit`,
`BlendMode=Opaque` (Masked only for dithered occlusion fade), usage flags `bUsedWithSkeletalMesh`,
`bUsedWithInstancedStaticMeshes`, `bUsedWithNiagaraSprites` as needed (set by Python, §11.4).

Ground option B' output = `BaseColor/π · E_sun · N·L · shadow + Emissive`. With the directional light intensity set to
**π lux × SunColor** and the post-process calibration of §6.7, a lit white ground under a vertical sun shows the same
value as an Unlit emissive 1.0, so lit ground and unlit characters stay colour-matched when the zone light changes.

### 6.5 Outlines (inverted hull) — platform constraints

The art spec (`art-inventory-ch1.md` §1.3) requires an inverted-hull outline with screen-constant width
(heroes 3.5 px at 1080p, monsters/NPCs 3.0, props 2.0, decor 1.2, ground none).

* **Skinned meshes cannot use a vertex-colour or UV-stored "smoothed normal" for WPO extrusion**: only position,
  normal and tangent are skinned; colours/UVs stay in bind pose, so extruding along them is wrong as soon as a limb
  rotates **[API]**. Blender's FBX/glTF exporters cannot write custom tangents either.
* **[Decision]** The Blender scripts **bake the hull as geometry**: duplicate the mesh, displace each vertex along the
  smoothed (averaged) normal by the category width converted to cm, flip winding, assign material slot `M_AF_Outline`
  (Unlit, opaque, single-sided, colour per category), keep the same vertex groups (skinned with the body). Width in cm
  for the fixed parity camera (FOV 30°, distance 2932 cm, `world-map-nav.md` §8):
  `cm_per_px@1080 = 2·tan(15°)·2932 / 1080 ≈ 1.455` → hero 3.5 px ≈ **5.1 cm**, monster/NPC 3.0 px ≈ 4.4 cm,
  props 2.0 px ≈ 2.9 cm, decor 1.2 px ≈ 1.7 cm. Because the camera distance is fixed, a constant world thickness is a
  constant fraction of the viewport height — exactly the "scale ∝ viewport height" rule of the art spec — on every
  resolution and device. If the camera pitch/distance changes (Q2 of `world-map-nav.md`), re-bake with the new factor.
* Static meshes may alternatively extrude in the material (WPO along `VertexNormalWS` × width × `2·CameraTanHalfFovY·
  distance/ViewSize.y`); keep one technique (baked) for simplicity.
* Hull cost: duplicates vertices/skinning of outlined meshes (within the art spec's budgets). Works with MSAA and needs
  no post-process pass. Mobile fallback (art spec): post-process Sobel on depth + custom stencil — mobile supports
  post-process materials with SceneDepth/CustomDepth only with MobileHDR on and costs a full-screen pass **[Verify]**.
* `UMeshComponent::SetOverlayMaterial(UMaterialInterface*)` (5.1+) **[API]** draws a second pass of the whole mesh with
  another material — useful for hit-flash/telegraph overlays, but it cannot cull front faces, so it is not the outline
  mechanism.

### 6.6 Blob shadows, decals, translucency

* Blob shadow = small translucent **Modulate** (or alpha-blended) quad mesh under each character, depth-tested, no
  shadow casting, scaled by the art spec's `k` rule; if terrain is not flat, use a `UDecalComponent` with a deferred
  decal material (supported in mobile forward as d-buffer decals since 5.5 **[Epic]**).
* VFX are additive/translucent; budget overdraw on mobile (≤ 600 live particles, `art-inventory-ch1.md` §1.9).
* Dithered opacity (occlusion fade) uses `DitherTemporalAA` in Masked materials (works with TSR/MSAA).

### 6.9 VFX without hand-authored Niagara assets

Sibling specs name Niagara systems (`NS_*`) as the 3D equivalent of web FX. Niagara emitters cannot practically be
authored from Python (module stacks are graph assets). **[Decision]** milestone 1 ports the web particle engine
(`FxEngine`, max 900 particles) as **code**: per FX material one pooled `UInstancedStaticMeshComponent` (camera-facing
quad or small mesh), instance transforms + `PerInstanceCustomData` (colour, alpha, frame, age) updated each frame on the
game thread (`BatchUpdateInstancesTransforms`, `SetCustomDataValue`) **[API]**; the material reads
`PerInstanceCustomData[n]`. Rings/discs/beams = pooled static-mesh components with dynamic material instances; trails =
`UProceduralMeshComponent` or ribbon quads. This gives exact web timings, works on every feature level and needs only
materials from Python. Niagara stays optional (Q6).

Camera shake: offset the camera component procedurally with the web's shake model (random jitter per frame for
`durationMs`, `intensity` as fraction of view) instead of `UCameraShakeBase` assets.

### 7.2 Option A design **[API]**

`UAnimSingleNodeInstance` already bypasses the anim graph by overriding its proxy's `Evaluate`; our class does the same.

```cpp
// AbyssAnimInstance.h
#pragma once
#include "Animation/AnimInstance.h"
#include "Animation/AnimInstanceProxy.h"
#include "AbyssAnimInstance.generated.h"

struct FAbyssAnimLayer
{
    const UAnimSequence* Seq = nullptr;
    float TimeSec = 0.f;
    bool bLoop = true;
};

struct FAbyssAnimProxy : public FAnimInstanceProxy
{
    FAbyssAnimProxy() = default;
    explicit FAbyssAnimProxy(UAnimInstance* Owner) : FAnimInstanceProxy(Owner) {}

    virtual void PreUpdate(UAnimInstance* InAnimInstance, float DeltaSeconds) override; // game thread: copy state
    virtual bool Evaluate(FPoseContext& Output) override;                               // worker thread

    FAbyssAnimLayer From, To;      // crossfade pair
    float ToWeight = 1.f;          // 0..1
    FAbyssAnimLayer Additive;      // e.g. HurtAdd
    float AdditiveWeight = 0.f;
};

UCLASS(Transient, NotBlueprintable)
class UAbyssAnimInstance : public UAnimInstance
{
    GENERATED_BODY()
public:
    // Start Seq, crossfading from the current clip over BlendMs (blend table: art-inventory-ch1.md §2.5).
    void Play(UAnimSequence* Seq, bool bLoop, float PlayRate, float BlendMs);
    void PlayAdditive(UAnimSequence* Seq, float Weight);
    void SetFrozen(bool bFrozen);   // hit-stop: freezes this actor's animation only (combat-feel.md §11.2)
protected:
    virtual FAnimInstanceProxy* CreateAnimInstanceProxy() override { return new FAbyssAnimProxy(this); }
    virtual void DestroyAnimInstanceProxy(FAnimInstanceProxy* P) override { delete static_cast<FAbyssAnimProxy*>(P); }
    virtual void NativeUpdateAnimation(float DeltaSeconds) override; // advances times/blend, fires named events
private:
    UPROPERTY(Transient) TObjectPtr<UAnimSequence> FromSeq;   // UPROPERTYs keep the sequences alive (GC)
    UPROPERTY(Transient) TObjectPtr<UAnimSequence> ToSeq;
    UPROPERTY(Transient) TObjectPtr<UAnimSequence> AdditiveSeq;
    float FromTime = 0.f, ToTime = 0.f, AddTime = 0.f, AddWeight = 0.f, Rate = 1.f, BlendElapsedMs = 0.f, BlendMs = 0.f;
    bool bFromLoop = true, bToLoop = true, bFrozen = false;
    friend struct FAbyssAnimProxy;
};
```

```cpp
// AbyssAnimInstance.cpp (evaluation part)
#include "AbyssAnimInstance.h"
#include "AnimationRuntime.h"

void FAbyssAnimProxy::PreUpdate(UAnimInstance* InAnimInstance, float DeltaSeconds)
{
    FAnimInstanceProxy::PreUpdate(InAnimInstance, DeltaSeconds);
    const UAbyssAnimInstance* I = CastChecked<UAbyssAnimInstance>(InAnimInstance);
    From = { I->FromSeq.Get(), I->FromTime, I->bFromLoop };
    To   = { I->ToSeq.Get(),   I->ToTime,   I->bToLoop };
    ToWeight = (I->BlendMs <= 0.f) ? 1.f : FMath::Clamp(I->BlendElapsedMs / I->BlendMs, 0.f, 1.f);
    Additive = { I->AdditiveSeq.Get(), I->AddTime, false };
    AdditiveWeight = I->AddWeight;
}

static void SampleLayer(const FAbyssAnimLayer& L, FPoseContext& Ctx)
{
    FAnimationPoseData Data(Ctx);
    L.Seq->GetAnimationPose(Data, FAnimExtractContext(double(L.TimeSec), /*bExtractRootMotion*/ false,
                                                      FDeltaTimeRecord(), L.bLoop));
}

bool FAbyssAnimProxy::Evaluate(FPoseContext& Output)
{
    if (!To.Seq) { Output.ResetToRefPose(); return true; }
    if (!From.Seq || ToWeight >= 1.f) {
        SampleLayer(To, Output);
    } else {
        FPoseContext A(Output), B(Output);
        SampleLayer(From, A);
        SampleLayer(To, B);
        FAnimationPoseData Out(Output);
        FAnimationRuntime::BlendTwoPosesTogether(FAnimationPoseData(A), FAnimationPoseData(B),
                                                 /*WeightOfPoseOne*/ 1.f - ToWeight, Out);
    }
    if (Additive.Seq && AdditiveWeight > 0.f) {
        FPoseContext Add(Output, /*bOverrideExpectsAdditivePose*/ true);
        SampleLayer(Additive, Add);
        FAnimationPoseData Base(Output);
        FAnimationRuntime::AccumulateAdditivePose(Base, FAnimationPoseData(Add), AdditiveWeight, AAT_LocalSpaceBase);
        Output.Pose.NormalizeRotations();
    }
    return true;   // true = the (empty) node graph is not evaluated
}
```

Rules:
* Times advance on the **game thread** in `NativeUpdateAnimation` (`Time += dt·Rate` unless frozen; loop with
  `fmod`, one-shots clamp at `GetPlayLength()`), so named events fire deterministically and the core stays the timing
  authority (contact/release ms are computed by the core, `combat-feel.md` §10; the clip is played at
  `1/speed` so its authored contact frame lines up).
* Named events (`Contact`, `Release`, `FootL`, `FootR`, `FX_*`, `WindupEnd`, `art-inventory-ch1.md` §2.5): **[Decision]**
  read from an exported `anim_events.json` (clip → `[{name, timeMs}]`, clip time at play rate 1), the same data the
  Blender scripts use; when the clip playhead crosses `timeMs / 1000` s (checked once per game-thread update, also
  across a loop wrap) the instance broadcasts the event to the owning actor. Optionally also authored as UE notifies
  (Python `unreal.AnimationLibrary.add_animation_notify_event`, §11.6) for editor preview; at runtime they can be read
  from `UAnimSequenceBase::Notifies` (`FAnimNotifyEvent::GetTriggerTime()`, `NotifyName`) — never both sources.
* Additive clips (`HurtAdd`) are imported with `AdditiveAnimType = AAT_LocalSpaceBase`, base pose = reference pose
  (set by Python, §11.6).
* Setup on the component:
  ```cpp
  Mesh->SetAnimationMode(EAnimationMode::AnimationBlueprint);   // also used for native UAnimInstance classes
  Mesh->SetAnimInstanceClass(UAbyssAnimInstance::StaticClass());
  UAbyssAnimInstance* Anim = Cast<UAbyssAnimInstance>(Mesh->GetAnimInstance());
  ```
* Crowd performance: `VisibilityBasedAnimTickOption = OnlyTickPoseWhenRendered`, `bEnableUpdateRateOptimizations` for
  monsters; keep `bUseMultiThreadedAnimationUpdate` (default) — the proxy only touches its own copies.
* `UAnimSequence::GetAnimationPose(FAnimationPoseData&, const FAnimExtractContext&)`,
  `FAnimationRuntime::BlendTwoPosesTogether(const FAnimationPoseData&, const FAnimationPoseData&, float, FAnimationPoseData&)`,
  `FAnimationRuntime::AccumulateAdditivePose(FAnimationPoseData&, const FAnimationPoseData&, float, EAdditiveAnimationType)`,
  the `FPoseContext(const FPoseContext&, bool)` constructor and `FAnimInstanceProxy::PreUpdate/Evaluate` are used by
  engine nodes (`FAnimNode_TwoWayBlend`, `FAnimNode_ApplyAdditive`, `FAnimSingleNodeInstanceProxy`) — **[Verify]** exact
  5.8 signatures; on mismatch, copy the calls from those engine nodes.

### 8.1 Enhanced Input objects created at runtime **[API]**

Actions and contexts are created in C++ (no `.uasset`s), owned by a `UObject` that keeps them alive
(`UPROPERTY() TObjectPtr<...>` — otherwise GC collects them). Names follow `save-ui-input.md` §5.6.

```cpp
#include "EnhancedInputComponent.h"
#include "EnhancedInputSubsystems.h"
#include "InputAction.h"
#include "InputMappingContext.h"
#include "InputModifiers.h"
#include "InputTriggers.h"

static UInputAction* MakeAction(UObject* Outer, FName Name, EInputActionValueType Type)
{
    UInputAction* A = NewObject<UInputAction>(Outer, Name);
    A->ValueType = Type;                         // Boolean / Axis1D / Axis2D / Axis3D
    return A;
}

void UAbyssInputConfig::Build()
{
    IA_Move  = MakeAction(this, TEXT("IA_Move"),  EInputActionValueType::Axis2D);
    IA_Click = MakeAction(this, TEXT("IA_Click"), EInputActionValueType::Boolean);
    IA_Back  = MakeAction(this, TEXT("IA_Back"),  EInputActionValueType::Boolean);
    // ... IA_Skill1..6, IA_Dodge, IA_TargetCycle, IA_ToggleAuto, IA_TownPortal, IA_AltClick, IA_Panel_*

    IMC_KBM = NewObject<UInputMappingContext>(this, TEXT("IMC_Gameplay_KBM"));
    { FEnhancedActionKeyMapping& M = IMC_KBM->MapKey(IA_Move, EKeys::W);
      M.Modifiers.Add(NewObject<UInputModifierSwizzleAxis>(IMC_KBM)); }           // X -> Y (default order YXZ)
    { FEnhancedActionKeyMapping& M = IMC_KBM->MapKey(IA_Move, EKeys::S);
      M.Modifiers.Add(NewObject<UInputModifierSwizzleAxis>(IMC_KBM));
      M.Modifiers.Add(NewObject<UInputModifierNegate>(IMC_KBM)); }
    { FEnhancedActionKeyMapping& M = IMC_KBM->MapKey(IA_Move, EKeys::A);
      M.Modifiers.Add(NewObject<UInputModifierNegate>(IMC_KBM)); }
    IMC_KBM->MapKey(IA_Move, EKeys::D);
    IMC_KBM->MapKey(IA_Click, EKeys::LeftMouseButton);
    IMC_KBM->MapKey(IA_Back, EKeys::Escape);

    IMC_Pad = NewObject<UInputMappingContext>(this, TEXT("IMC_Gameplay_Gamepad"));
    { FEnhancedActionKeyMapping& M = IMC_Pad->MapKey(IA_Move, EKeys::Gamepad_Left2D);
      UInputModifierDeadZone* DZ = NewObject<UInputModifierDeadZone>(IMC_Pad);
      DZ->LowerThreshold = 0.2f;  M.Modifiers.Add(DZ); }

    IMC_Touch = NewObject<UInputMappingContext>(this, TEXT("IMC_Touch"));
    IMC_Touch->MapKey(IA_Back, EKeys::Android_Back);                              // Android system back
}

{

            ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(GetLocalPlayer()))
    {
        Sub->AddMappingContext(Config->IMC_KBM, 0);

{
    Super::SetupInputComponent();
    UEnhancedInputComponent* EIC = CastChecked<UEnhancedInputComponent>(InputComponent); // needs DefaultInput.ini §5.2
    EIC->BindAction(Config->IA_Move,  ETriggerEvent::Triggered, this, &ThisClass::OnMove);      // (const FInputActionValue&)
    EIC->BindAction(Config->IA_Click, ETriggerEvent::Started,   this, &ThisClass::OnClickStarted);
    EIC->BindAction(Config->IA_Click, ETriggerEvent::Triggered, this, &ThisClass::OnClickHeld);  // every frame while held
    EIC->BindAction(Config->IA_Click, ETriggerEvent::Completed, this, &ThisClass::OnClickReleased);
    EIC->BindTouch(IE_Pressed,  this, &ThisClass::OnTouchPressed);   // (ETouchIndex::Type, FVector Location)
    EIC->BindTouch(IE_Repeat,   this, &ThisClass::OnTouchMoved);
    EIC->BindTouch(IE_Released, this, &ThisClass::OnTouchReleased);

```

Pitfalls:
* `MapKey` returns a **reference into the context's mapping array**; finish editing one mapping before the next
  `MapKey` (the array may reallocate). Use only the public `MapKey/UnmapKey` API — the internal storage moved in recent
  versions (`DefaultKeyMappings`/profile overrides) **[Forum]**.
* After editing a context that is already added, call `Sub->RequestRebuildControlMappings()`.
* Do not use `UInputTriggerCombo` (deprecated in 5.8) **[Epic]**. Default trigger (none) = `Triggered` every frame
  while actuated; add `UInputTriggerPressed`/`Released` only where the web uses edge semantics.
* Panel hotkeys (I, K, M, H, C, P, U, J, O, R, V, Q, Tab, Space, 1–6) are one `Boolean` action each, mapped in `IMC_KBM`.

### 8.2 Virtual controls feed the same actions

Touch buttons and the joystick (Slate widgets, §9) call into Enhanced Input so gameplay code has a single path:

```cpp
Sub->InjectInputForAction(Config->IA_Skill1, FInputActionValue(true), {}, {});          // button press
Sub->InjectInputForAction(Config->IA_Move, FInputActionValue(FVector2D(Jx, Jy)), {}, {}); // joystick, every tick while held
```

(`IEnhancedInputSubsystemInterface::InjectInputForAction(const UInputAction*, FInputActionValue RawValue,
const TArray<UInputModifier*>&, const TArray<UInputTrigger*>&)`; `StartContinuousInputInjectionForAction` /
`StopContinuousInputInjectionForAction` also exist **[API]/[Verify]**.) Discrete web events (`ui:skill_click`,
`ui:dodge_request`, `ui:target_cycle`, `save-ui-input.md` §4) map to these actions; the UI never calls the core
directly for gameplay input.

### 8.3 Touch specifics

* World taps (click-to-move, tap a monster/NPC/loot) come from `BindTouch` on the player controller; Slate widgets that
  handle a touch return `FReply::Handled()`, so a press on a control never reaches the world (equivalent of the web's
  pointer claiming, `save-ui-input.md` §5.7.4). Touch position: the `FVector Location` (viewport px) or
  `GetInputTouchState(ETouchIndex::Touch1, X, Y, bPressed)`.
* Up to 4 simultaneous touches are used by the web (`TOUCH_POINTERS = 4`); Slate supports 10.
* Desktop testing of the touch layout: launch with `-faketouches` (mouse produces touch events) or force the layout
  setting.
* On mobile, touches do not generate `LeftMouseButton`; keep the mouse and touch bindings separate.
* Gestures: none (no pinch/zoom); `bEnableGestureRecognizer=False`.

### 8.4 Picking the ground and actors (no collision)

* Ground point: `PC->DeprojectScreenPositionToWorld(X, Y, Origin, Dir)` then intersect with the ground plane
  `Z = 0` (or the terrain height function if terrain is not flat): `t = (GroundZ − Origin.Z)/Dir.Z`, `P = Origin + t·Dir`,
  `tile = (P.X/100, P.Y/100)` (`world-map-nav.md` §1.3–1.4).
* Actors: project candidate actors' screen bounds with `ProjectWorldLocationToScreen` and pick the closest under the
  pointer, mirroring the web's sprite hit areas; no `GetHitResultUnderCursor` traces (collision is disabled on gameplay
  meshes for mobile performance).
* Mouse position in viewport px: `GetMousePosition`; convert to Slate units by dividing by the DPI scale
  (`GetDefault<UUserInterfaceSettings>()->GetDPIScaleBasedOnSize(ViewportSize)`) — the analogue of `logicalPointer()`
  (`src/config.ts:26-29`).

### 8.5 Input mode and cursor

`SetInputMode(FInputModeGameAndUI().SetHideCursorDuringCapture(false).SetLockMouseToViewportBehavior(EMouseLockMode::DoNotLock))`,
`bShowMouseCursor = true` on desktop, `bEnableClickEvents = false`, `bEnableTouchEvents = true`.

## 9. UI fully in C++

### 9.1 Slate vs UMG

| | Slate (`SCompoundWidget`) | UMG built from C++ (`UUserWidget` + `WidgetTree->ConstructWidget`) |
|---|---|---|
| Authoring in code | declarative `SNew(...)[...]` — concise | verbose (`ConstructWidget`, `AddChildTo…`, slot setters); must build in `Initialize()`/`RebuildWidget()` (building in `NativeConstruct` shows nothing) **[Forum]** |
| Assets needed | none | none for native classes (`CreateWidget<UMyWidget>(PC, UMyWidget::StaticClass())`) |
| DPI scaling, touch, mobile | yes (UMG renders through Slate) | yes |
| GC | widgets are not UObjects: hold UObjects via `TStrongObjectPtr`/an owning UObject | UObject-native |
| Later CommonUI / gamepad navigation | possible (wrap in UMG) | native |

**[Decision] Slate** for HUD, panels, story overlay and touch controls. Sibling specs say "UMG"/`WBP_*`; read that as
"the UE UI layer" — the layout numbers carry over 1:1 in Slate units (§9.2). Screens are added with
`GEngine->GameViewport->AddViewportWidgetContent(SNew(SAbyssHud)..., ZOrder)` and removed with
`RemoveViewportWidgetContent` on world teardown. Content added this way sits under the game viewport's DPI scaler, so
it is scaled like UMG **[API]**.

Slate building blocks: `SOverlay` (layers), `SConstraintCanvas` (anchored absolute layout = web x/y layouts),
`SBox` (fixed sizes), `SVerticalBox`/`SHorizontalBox`, `SScrollBox` (touch drag-scroll), `STextBlock`
(`ShadowOffset`, `ShadowColorAndOpacity`, font `OutlineSettings` for the web's text strokes), `SImage` with
`FSlateBrush` (`SetResourceObject(UTexture2D* or UMaterialInstanceDynamic*)`), `SButton` (`TouchMethod`/`PressMethod`
= `PreciseTap` inside scroll boxes), custom leaf widgets with `OnPaint` (`FSlateDrawElement::MakeBox/MakeLines`).
Cooldown sweeps / radial fills: UI-domain material (`MaterialDomain = MD_UI`) with a `Fraction` parameter used as a
brush. Gradient text (title gradients): `FSlateFontInfo::FontMaterial` with a UI material. Tweens: port Phaser's easing
equations (Back/Quad/Cubic/Sine, `s = 1.70158`) into a small header — `FCurveSequence`'s built-in easings lack Back.
Performance: wrap rarely-changing panels in `SInvalidationPanel` or enable global invalidation
(`Slate.EnableGlobalInvalidation=1`) **[Verify]**; avoid per-frame text rebuilds.

### 9.2 DPI scaling

* `UIScaleRule=ScaleToFit`, `DesignScreenSize=(1280,720)` ⇒ `scale = min(W/1280, H/720)` (W, H = viewport in physical
  pixels). Every web logical px number is **1 Slate unit**. On wider screens the layout area is wider than 1280 (anchor
  HUD elements to edges as the web does); on 4:3 iPads it is taller than 720 (never narrower than 1280).
  `ApplicationScale` multiplies the result (per-platform override, §5.5).
* If a physical-size rule is needed later (phones), implement `UAbyssDPIScalingRule : UDPICustomScalingRule`
  (`virtual float GetDPIScaleBasedOnSize(FIntPoint Size) const`) and set `UIScaleRule=Custom`,
  `CustomScalingRuleClass=/Script/Abyssfire.AbyssDPIScalingRule` **[API]**.
* Desktop high-DPI windows: `bAllowHighDPIInGameMode=True` (otherwise Windows scales a low-res backbuffer).
* Font sizes: Slate font size is in points at 96 DPI → a web `Npx` font = Slate size **`N × 0.75`**.

### 9.3 Safe areas

Wrap each full-screen root in `SSafeZone` (iPhone notch / Dynamic Island, Android cutouts with `bUseDisplayCutout=True`).
Full-bleed backgrounds (letterbox bars of story scenes, fades) go *outside* the safe zone.

### 9.4 Fonts (CJK)

Web: body `"Noto Sans SC", sans-serif`, titles `"Cinzel", "Noto Sans SC", serif` (`src/ui/UiKit.ts:19-20`), story/boss
`"Noto Serif SC"` (`save-ui-input.md` §8); zh-TW strings are generated from zh-CN (`src/i18n/index.ts:18-31`).
UE has no system-font fallback in packaged games → **bundle the fonts**:

* Files in `unreal/Fonts/` (OFL): `NotoSansSC-Regular/Bold`, `NotoSansTC-Regular/Bold`, `NotoSerifSC-Regular/Bold`,

  every character occurring in the exported zh-CN, zh-TW and en string tables (+ CJK punctuation): a full Noto Sans SC
  weight is ≈ 10–16 MB, a subset ≈ 1–2 MB.
* Load at runtime without assets (staged UFS, §10.1) **[API]**:


* Many distinct CJK glyphs can flush the font atlas; watch `Slate.MaxFontAtlasPagesBeforeFlush` **[Verify]**.

### 9.5 Touch-control sizes

The web specifies touch sizes in CSS px and converts with `k = clamp(max(displayScale), 1, 2)` game px per CSS px
(`src/systems/MobileControlsSystem.ts:26-44`, `save-ui-input.md` §5.7.1). Equivalent in UE:
`DPR = densityDpi / 160` (Android dp; iOS ≈ ppi/163 per point), `k = clamp(DPR / DPIScale, 1, 2)`, `px(c) = round(c·k)`
Slate units, where `densityDpi` comes from `FPlatformApplicationMisc::GetPhysicalScreenDensity(int32&)` (returns an
accuracy enum; on `Unknown` use DPR = 1) **[API]/[Verify]**. Proof: web `displayScale = 1/fitCss`, UE `DPIScale = fitCss·DPR`,
so `DPR/DPIScale = 1/fitCss` — the same k.

### 9.6 World-anchored UI

HP bars, names, damage numbers, quest markers: one Slate overlay layer (`SConstraintCanvas`) whose children are
positioned every frame from `ProjectWorldLocationToScreen` (pooled widgets) — cheaper on mobile than one
`UWidgetComponent` per actor. Divide projected viewport px by the DPI scale to get Slate units.

### 9.7 Text from the core

Core strings are UTF-8 `std::string`; convert with `FString(UTF8_TO_TCHAR(s.c_str()))` (or `StringCast<TCHAR>` with a
length) and display with `FText::FromString` / `FText::AsCultureInvariant` (UE's localisation pipeline is not used;
the core owns the string tables). Reverse: `FTCHARToUTF8 Conv(*Str); std::string(Conv.Get(), Conv.Length())`.

## 10. Data files, cooking, saves

### 10.1 Staging exported JSON (and fonts)

* **[Decision]** Exported tables live in `unreal/Data/*.json`; `Abyssfire.Build.cs` adds
  `RuntimeDependencies.Add("$(ProjectDir)/Data/...", StagedFileType.UFS)` (`...` = recursive) so they are packed into the
  pak/IoStore container on every platform; same for `$(ProjectDir)/Fonts/...` **[API]/[Verify]** (smoke test: the game
  logs the number of tables loaded at boot on each device).
* UFS (inside the pak) is required on Android/iOS: loose files are not reachable through normal paths there; only UE's
  `IPlatformFile` (pak-aware) can open them. **NonUFS** staging is only for third-party code that does its own I/O
  (not our case) **[Epic]**.
* Fallback: `+DirectoriesToAlwaysStageAsUFS=(Path="...")` in `DefaultGame.ini` (path relative to `Content/`).

### 10.2 Reading data at runtime

```cpp
TArray<uint8> Bytes;
const FString Path = FPaths::ProjectDir() / TEXT("Data/items.json");   // works in editor and in packaged builds
if (FFileHelper::LoadFileToArray(Bytes, *Path))
{
    const std::string_view Json(reinterpret_cast<const char*>(Bytes.GetData()), size_t(Bytes.Num()));
    abyss::LoadResult R = DataRegistry.Load("items", Json);              // core parses (no exceptions)
    // log R.errors through UE_LOG
}
```

The core never opens files. All tables load once at boot (synchronously, a few hundred KB); a data error is fatal in
development builds and logged in shipping.

### 10.3 Cooking runtime-loaded assets

Because zones are built at runtime from data (meshes/anims/materials resolved by path through `art_manifest.json`),
the cooker sees no references: `+DirectoriesToAlwaysCook=(Path="/Game/Abyssfire")` (§5.3). Load by path:
`LoadObject<USkeletalMesh>(nullptr, TEXT("/Game/Abyssfire/Characters/Heroes/SK_Hero_Warrior.SK_Hero_Warrior"))`
(sync) or `UAssetManager::GetStreamableManager().RequestAsyncLoad(Paths, Callback)` / the 5.5+ `LoadAssetAsync` during
the zone-load screen. Keep loaded assets referenced from a `UGameInstanceSubsystem` (`UPROPERTY() TArray<TObjectPtr<UObject>>`)
so GC does not unload them between zones (the web keeps sheets for the last 1–2 zones; CLAUDE.md "Performance").

### 10.4 Single map, runtime-built zones **[Decision]**

One persistent map `L_Main` (created by Python, §11.7) containing nothing but world settings; the `Abyssfire` module
spawns the zone (terrain/props as `UHierarchicalInstancedStaticMeshComponent`s, sun, fog, post-process, characters) from
core data and tears it down on zone change — no `OpenLevel`, no level streaming, no lighting builds. Matches the web
(one `ZoneScene` rebuilt per zone) and keeps mobile zone switches fast. Q9 covers per-zone `.umap`s instead.

### 10.5 Saves and settings — platform notes

`save-ui-input.md` §3.10 specifies `ISaveStorage` with JSON files under `FPaths::ProjectSavedDir()/SaveGames/`
(atomic tmp → rename, `.bak` fallback). Platform notes:
* All four platforms can write under `FPaths::ProjectSavedDir()` through `IPlatformFile` (`MoveFile` for the rename).
  The physical location differs (Windows `%LOCALAPPDATA%\Abyssfire\Saved`, macOS user Library, iOS app sandbox
  Documents, Android app-specific storage) **[Verify]** on each device; never hard-code paths.
* Alternative with platform save-system integration (iCloud later): `UGameplayStatics::SaveDataToSlot(const TArray<uint8>&,
  const FString& Slot, int32 UserIndex)` / `LoadDataFromSlot` with the core's JSON bytes **[API]**.
* Settings (locale default **zh-CN**, `src/i18n/index.ts:14-15`; audio volumes; quality tier; control layout) go into a

* Save on `FCoreDelegates::ApplicationWillDeactivateDelegate` / `ApplicationWillEnterBackgroundDelegate` (mobile; must

## 11. Editor Python automation (content build)

### 11.1 Running scripts

* Plugin `PythonScriptPlugin` (editor only). Embedded **CPython 3.11** in 5.8 **[Forum, Epic staff]**; scripts use the
  standard library only.
* Headless (no UI, fast) — imports, materials, maps:
  * Windows: `"C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<repo>\unreal\Abyssfire.uproject" -run=pythonscript -script="<repo>\unreal\Scripts\build_content.py" -unattended -nosplash -nop4 -stdout -FullStdOutLogOutput`
  * macOS: `"/Users/Shared/Epic Games/UE_5.8/Engine/Binaries/Mac/UnrealEditor.app/Contents/MacOS/UnrealEditor" "<repo>/unreal/Abyssfire.uproject" -run=pythonscript -script="<repo>/unreal/Scripts/build_content.py" -unattended -nosplash -stdout` **[Verify]** whether 5.8 ships a separate `UnrealEditor-Cmd` on Mac.
  * Arguments after the script path inside `-script="build_content.py --family heroes"` reach `sys.argv`.
* Full editor (needed for thumbnails or anything requiring a level viewport): `UnrealEditor <uproject>
  -ExecutePythonScript="<script>" -unattended -nosplash` and end the script with `unreal.SystemLibrary.quit_editor()`.
* The C++ editor target must be **built first** (scripts reference project classes such as the notify or game-mode
  classes).
* Always use `obj.set_editor_property(name, value)` (fires `PostEditChangeProperty`, e.g. resolving a material
  collection parameter's GUID); plain attribute assignment does not. A wrong property name raises — scripts must fail
  loudly. Use `help(unreal.X)` / `dir()` to confirm names on 5.8 **[Verify]**.
* Scripts are **idempotent**: re-running replaces assets (`replace_existing=True`) and saves
  (`unreal.EditorAssetLibrary.save_directory("/Game/Abyssfire")` or per-asset `save_loaded_asset`).

### 11.2 Pipeline order

1. Build `AbyssfireEditor` (C++). 2. Blender scripts export FBX/PNG (`art-inventory-ch1.md` §2). 3. `build_content.py`:
textures → skeletal meshes (create skeletons) → animations (onto those skeletons) → static meshes → materials, MPC and
material instances → assign materials → anim settings/notifies → audio WAVs (`audio.md` §9) → map `L_Main` → save all.
4. Package (§12).

### 11.3 Importing FBX / glTF (Interchange)

Interchange is the FBX/glTF path in 5.5+ **[Epic]**. Prefer **synchronous `AssetImportTask`s** — the scripted
`InterchangeManager.import_asset` runs asynchronously and a commandlet can exit before it finishes **[Forum]**.

```python
import unreal

ASSET_TOOLS = unreal.AssetToolsHelpers.get_asset_tools()

def make_pipeline(skeleton=None, anims_only=False):
    # Start from the engine's default assets pipeline (path [Verify] in 5.8), then override fields.
    base = unreal.load_asset("/Interchange/Pipelines/DefaultAssetsPipeline")
    p = unreal.InterchangeGenericAssetsPipeline()
    # copy what we need explicitly instead of relying on defaults that change between versions:
    meshes = p.get_editor_property("common_meshes_properties")
    meshes.set_editor_property("vertex_color_import_option",
                               unreal.InterchangeVertexColorImportOption.IVCIO_REPLACE)   # [Verify] enum
    skm = p.get_editor_property("common_skeletal_meshes_and_animations_properties")
    if skeleton:
        skm.set_editor_property("skeleton", skeleton)                                   # required for anims
    skm.set_editor_property("import_only_animations", anims_only)
    mats = p.get_editor_property("material_pipeline")
    mats.set_editor_property("material_import",
                             unreal.InterchangeMaterialImportOption.DO_NOT_IMPORT)       # [Verify] enum; UE materials come from §11.4
    return p

def import_file(src, dest_path, pipeline):
    task = unreal.AssetImportTask()
    task.set_editor_property("filename", src)
    task.set_editor_property("destination_path", dest_path)
    task.set_editor_property("automated", True)
    task.set_editor_property("replace_existing", True)
    task.set_editor_property("save", True)
    task.set_editor_property("async_", False)
    stack = unreal.InterchangePipelineStackOverride()
    stack.add_pipeline(pipeline)                                                         # [Verify] method name
    task.set_editor_property("options", stack)
    ASSET_TOOLS.import_asset_tasks([task])
    paths = task.get_editor_property("imported_object_paths")
    if not paths:
        raise RuntimeError("import failed: " + src)
    return paths
```

* With Interchange the asset **name comes from the pipeline / source file name**; `destination_name` is ignored
  **[Epic]** → the Blender export file name must already be the UE asset name (`art-inventory-ch1.md` §2.2 does this).
* One animation per FBX (`A_<Family>_<Name>_<Action>.fbx`), imported with `import_only_animations=True` and the family
  skeleton. Skeleton-less animation FBX no longer imports as animation in 5.7+ **[Forum]** — every anim FBX contains
  the armature with a `root` bone.
* Legacy FBX fallback (if Interchange misbehaves for a family): set `Interchange.FeatureFlags.Import.FBX False`
  (console/`DefaultEngine.ini [ConsoleVariables]`) and pass `unreal.FbxImportUI()` as `options`
  (`import_as_skeletal`, `skeleton`, `import_animations`, `skeletal_mesh_import_data.vertex_color_import_option`) — a
  5.7 report says the flag no longer restores all 5.6 behaviour **[Forum]**.
* glTF (`.glb`) also imports through Interchange; FBX is the path specified by the art pipeline.
* Textures: palette textures `T_*_P` linear (`srgb=False`), all palette/icon textures `mip_gen_settings =
  TMGS_NO_MIPMAPS`, `filter = TF_NEAREST` for palettes, `lod_group = TEXTUREGROUP_UI` for icons; compression
  `TC_DEFAULT` (ASTC on mobile via cook flavor) or `TC_USER_INTERFACE2D` for UI.
* Audio: `.wav` → `SoundWave` (set `looping` for music; compression per `audio.md`).

### 11.4 Materials from Python (`MaterialEditingLibrary`)

```python
MEL = unreal.MaterialEditingLibrary

def make_toon_master():
    m = ASSET_TOOLS.create_asset("M_AF_Toon", "/Game/Abyssfire/Materials", unreal.Material, unreal.MaterialFactoryNew())
    m.set_editor_property("shading_model", unreal.MaterialShadingModel.MSM_UNLIT)
    m.set_editor_property("used_with_skeletal_mesh", True)
    m.set_editor_property("used_with_instanced_static_meshes", True)
    base = MEL.create_material_expression(m, unreal.MaterialExpressionVectorParameter, -900, 0)
    base.set_editor_property("parameter_name", "BaseColor")
    sun = MEL.create_material_expression(m, unreal.MaterialExpressionCollectionParameter, -900, 200)
    sun.set_editor_property("collection", unreal.load_asset("/Game/Abyssfire/Materials/MPC_AF_Lighting"))
    sun.set_editor_property("parameter_name", "SunDir")
    n = MEL.create_material_expression(m, unreal.MaterialExpressionPixelNormalWS, -900, 400)
    cust = MEL.create_material_expression(m, unreal.MaterialExpressionCustom, -500, 0)
    cust.set_editor_property("output_type", unreal.CustomMaterialOutputType.CMOT_FLOAT3)
    cust.set_editor_property("code", TOON_HLSL)                     # §6.4
    inputs = []
    for name in ("N", "L", "Base", "ShadowAmt", "LightAmt", "TShade", "TLight", "W"):
        ci = unreal.CustomInput(); ci.set_editor_property("input_name", name); inputs.append(ci)
    cust.set_editor_property("inputs", inputs)
    MEL.connect_material_expressions(n, "", cust, "N")
    MEL.connect_material_expressions(sun, "", cust, "L")
    MEL.connect_material_expressions(base, "", cust, "Base")
    # ... scalar parameters for the remaining inputs, rim / overlays ...
    MEL.connect_material_property(cust, "", unreal.MaterialProperty.MP_EMISSIVE_COLOR)
    MEL.layout_material_expressions(m)
    MEL.recompile_material(m)
    unreal.EditorAssetLibrary.save_loaded_asset(m)
    return m

def make_instance(name, parent, vectors, scalars):
    mi = ASSET_TOOLS.create_asset(name, "/Game/Abyssfire/Materials/Instances",
                                  unreal.MaterialInstanceConstant, unreal.MaterialInstanceConstantFactoryNew())
    MEL.set_material_instance_parent(mi, parent)
    for k, v in vectors.items(): MEL.set_material_instance_vector_parameter_value(mi, k, v)
    for k, v in scalars.items(): MEL.set_material_instance_scalar_parameter_value(mi, k, v)
    MEL.update_material_instance(mi)
    unreal.EditorAssetLibrary.save_loaded_asset(mi)
    return mi
```

* MPC: `create_asset("MPC_AF_Lighting", path, unreal.MaterialParameterCollection, unreal.MaterialParameterCollectionFactoryNew())`,
  then set `vector_parameters` / `scalar_parameters` to lists of `unreal.CollectionVectorParameter` /
  `unreal.CollectionScalarParameter` (`parameter_name`, `default_value`). Create the MPC **before** materials that use it.
* With Substrate **off**, `connect_material_property` targets the classic root pins (`MP_BASE_COLOR`, `MP_EMISSIVE_COLOR`,
  `MP_OPACITY_MASK`, `MP_WORLD_POSITION_OFFSET`, …). If Substrate were on, new materials would still use the legacy
  root and be converted at compile time **[Epic]** — but do not depend on that.
* Other properties set from Python: `blend_mode` (`unreal.BlendMode.BLEND_MASKED/BLEND_TRANSLUCENT/BLEND_ADDITIVE/BLEND_MODULATE`),
  `two_sided`, `material_domain` (`MD_SURFACE`, `MD_UI`, `MD_DEFERRED_DECAL`, `MD_POST_PROCESS`), usage flags.
* Assign: `static_mesh.set_material(index, mi)`; skeletal: copy `skm.get_editor_property("materials")`, set each
  `SkeletalMaterial.material_interface`, write back with `set_editor_property("materials", arr)`.
* Material functions: `MaterialFunctionFactoryNew` + `MEL.create_material_expression_in_function(...)`.

```python
def make_main_map():
```

## 13. Runtime concerns on mobile

| Concern | Rule |
|---|---|
| App lifecycle | Pause the core sim and save on `ApplicationWillDeactivateDelegate` / `ApplicationWillEnterBackgroundDelegate`; resume on `ApplicationHasEnteredForegroundDelegate`. Clamp the frame delta after resume (the core's fixed-step accumulator must not run thousands of steps) |
| Orientation | Landscape only (both landscape directions); the web's rotate card (`MobileShell.ts:13-78`) is unnecessary |
| Full screen | Android immersive (`bFullScreen`), iOS status bar hidden; display cutout + `SSafeZone` |
| Screen sleep | `FPlatformApplicationMisc::ControlScreensaver(FGenericPlatformApplicationMisc::EScreenSaverAction::Disable)` while in gameplay **[API]** |
| Frame rate | 60 fps cap (`FrameRateLock`, `t.MaxFPS=60`); low-tier devices may use 30 via device profile; the core sim stays at its fixed step |
| Collision / physics | Disable collision and overlap events on all gameplay meshes (`SetCollisionEnabled(ECollisionEnabled::NoCollision)`, `SetGenerateOverlapEvents(false)`); no physics simulation; no NavMesh |
| Ticking | One driver (`UTickableWorldSubsystem` or the game mode) ticks the core; actors are views with tick disabled where possible |
| Memory | Texture budgets per art spec; keep only current + previous zone assets referenced on touch devices (web `sheetKeepZones` 1 on touch, 2 on desktop, CLAUDE.md) |
| Audio | Engine handles OS interruptions; music/SFX volumes from settings |

## 18. Open questions

* **Q1** Engine pin: 5.8.3 now; adopt later 5.8.x hotfixes automatically? (Recommended: yes, hotfixes only.)
* **Q2** Desktop AA/renderer: deferred + TSR (default) vs forward + MSAA (crisper outlines; blocked by the M1/M2 bug until verified fixed).
* **Q3** Mobile shading path: forward (recommended) vs 5.8's default multi-pass deferred.
* **Q4** UI technology: Slate (recommended) vs UMG-from-C++ (sibling specs say UMG / `WBP_*`).
* **Q5** Animation: core-timed crossfade player without montages (recommended) vs montage support via slot evaluation (A+).
* **Q6** VFX: code-driven ISM particles (recommended, scriptable) vs Niagara assets (`NS_*` in sibling specs; not authorable from Python).
* **Q7** Outline: Blender-baked hull (recommended; skinning-correct) vs material WPO with smoothed normals (art spec; wrong on skinned meshes because colours/UVs are not skinned).
* **Q8** Data staging: `RuntimeDependencies` from `unreal/Data` (recommended) vs `DirectoriesToAlwaysStageAsUFS` under `Content/`.
* **Q9** One persistent map with runtime-built zones (recommended) vs one `.umap` per zone.
* **Q10** Real sun shadows on mobile high tier (1–2 CSM cascades) or blob-only on all phones (art spec: blob only on mobile).
* **Q11** Bundle id / package name / Apple team / Play account / company name (`REPLACE_ME` placeholders).
* **Q12** Revisit Substrate Toon for the desktop build once it supports forward and leaves experimental (would split the look per platform).
* **Q13** Windows shader model SM5-only (recommended) vs SM6.
* **Q14** Android: keep GLES 3.2 fallback (reach) or Vulkan-only (fewer shader variants, simpler QA).
* **Q15** Phone UI size: web-parity ScaleToFit 1280×720 vs a larger `ApplicationScale` / custom DPI rule on small phones.

# Port Spec — Art Inventory & 3D Asset Spec (Chapter 1: `emerald_plains`)

Area owner: art pipeline (Blender Python → FBX → UE 5.8). Web source of truth: branch `claude/unreal-rebuild`,
procedural drawers under `src/graphics/` (2D canvas, cel-shaded, ink-outlined sprites).
Target: a **true 3D** game with a fixed oblique camera (yaw −135°, pitch −30°, FOV 30°, see `world-map-nav.md` §8),
stylised **cel-shaded + outlined** real 3D assets generated by Blender Python scripts (no placeholders), shipped on
macOS / Windows / Android / iOS.

This document lists **every visual asset Chapter 1 needs** and specifies each one precisely enough (palette hex
codes, proportions, silhouettes, animation lists with ms and contact/release beats, VFX timings) that an artist /
script author who never opens the TypeScript can rebuild the web game's look in 3D. It also fixes the look
(shader model), the naming conventions, the skeletons and their sharing, and the JSON tables the art pipeline
consumes. Systems are described **generally** (heroes, humanoid monsters, NPC kit, decor, FX library) with the
Chapter-1 instances listed explicitly; later chapters add rows, not new mechanisms.

Citations are `path:line` at the time of writing. "**render-only**" marks web artefacts of the 2D/isometric renderer
(sprite sheets, mirrored views, "far" tones, iso squash, depth offsets) together with their 3D equivalent.
"**NEW**" marks something the web does not have that the 3D port needs (or that this spec recommends); every NEW item
is flagged so a parity build can skip it.

Related specs (not repeated here): combat timing and hit feel `combat-feel.md` (§10 contact beats, §11 hit
profiles), monsters `monsters-ai.md` (§2.5 art notes), world/terrain/camera `world-map-nav.md` (§1.3 units, §8 camera,
§14 atmosphere, §15 terrain/decor placement), quests/story `quests-story-ch1.md` (§6 NPCs, §8.6 portraits), UI kit
`save-ui-input.md` (§8 UiKit), loot `loot-items-inventory.md` (§5.9 Chapter-1 item pool).

### 0.2 Time
All durations in **ms** at play-rate 1. Blender animation is authored at **60 fps** (frame = ms × 0.06, rounded);
contact/release notifies are placed at the exact ms (UE notifies are not frame-quantised). The core sim decides when
damage lands (`combat-feel.md` §10); animation notifies are cosmetic sync only.

### 0.3 Review camera
Every asset is reviewed (Blender turntable + UE review map) under the game camera: yaw −135°, pitch −30°, horizontal
FOV 30°, distance 2 932 cm to a focus 50 cm above ground (`world-map-nav.md` §8) → a 1.75 m hero is ≈ 25 % of the
screen height at 720p logical. Readability rule from the web (`docs/art-direction.md:9-11`): details under ~2 texture px
vanish → **no detail smaller than ~4 cm on characters, ~8 cm on props** unless it is an emissive accent.

## 1. The look — stylised 3D cel shading that keeps the web identity

### 1.1 Identity rules (from `docs/art-direction.md`, translated to 3D)

| Web rule (`docs/art-direction.md`) | 3D rule |
|---|---|
| "Cel-shaded cartoon: 2–3 tones per material, coloured (not black) line art, crisp silhouettes, no noisy per-pixel texture" (`:18-20`) | Toon master material with **3 bands** (shade / base / light) computed from one base colour (§1.2); flat colour regions, no photo/noise textures, no PBR roughness variation. Line art = inverted-hull outline + painted crease lines (§1.3). |
| "Light comes from the upper left. Shadows lean cool (purple/blue), highlights warm" (`:12`) | One directional "key" light from **screen upper-left** (`world-map-nav.md` §14.1: yaw 0°, pitch ≈ −45°); shade band tinted toward `#1E143C` (cool violet), light band toward `#FFF4D6` (warm) — exactly the web `tone()` mix (§1.2). |
| Value hierarchy: characters (inked, saturated) > interactive props (softer ink) > decorations (thin line art, no heavy outline) > ground (lowest contrast, no outlines) (`:21-23`) | Outline width/colour per category (§1.3 table), saturation budget per category (§1.5). |
| "Every object needs a clear silhouette and one focal accent (glow, colour pop) at most" (`:24-25`) | One emissive accent per prop (e.g. altar rune, chest seam, hearth gem); characters: one glow point (warrior visor ember, mage crystal, rogue amber eyes, chief eye embers, shaman spirit-fire). |
| Zone palette: Emerald Plains = warm sunlit greens, ochre paths, golden highlights (`:26-27`) | Plains terrain/foliage palette §6; post-process grade from `world-map-nav.md` §14.1 (plains row). |
| UI quality colours normal `#c8c8c8`, magic `#4f8cff`, rare `#ffd84a`, legendary `#ff8a2a`, set `#3ecf6a` (`:38-39`) | Canonical quality palette for loot beams, bag tints, labels, icon frames (QUIRK A1: the web uses three slightly different palettes, §12). |

### 1.2 Toon shading model (exact port of `tone()` / `cel()`)

Every web material is built from **one base colour** by `tone(base, {shadow, light})`
(`src/graphics/sprites/rig/Rig.ts:144-154`):
```
c      = base (RGB 0..255)
shade  = mix( mix(c, (30,20,60), 0.35), (0,0,0), shadow )        // shadow default 0.42
light  = mix( c, (255,244,214), light )                          // light  default 0.32
line   = mix( mix(c, (20,10,30), 0.5), (0,0,0), 0.55 )           // coloured line art
mix(a,b,t) = a + (b − a)·t   (per channel, sRGB values)
```
`cel(path, tone)` fills a shape with the **shade** colour, overlays the **light** colour offset toward the upper-left
by `band` and the **base** colour offset by `band − hi` (`Rig.ts:163-200`): the visible result is a narrow light
crescent on the upper-left rim, a broad base area, and a shade band on the lower-right — then a thin `line` stroke.

**3D master material `M_AF_Toon` (UE, Unlit shading model + custom lighting, mobile-safe):**
```
NdotL'   = dot(N, L_key) · 0.5 + 0.5                    // half-Lambert, L_key = screen upper-left sun
          × shadowAttenuation (dynamic shadow / blob)   // optional on mobile
band     = NdotL' < T_shade ? SHADE : (NdotL' > T_light ? LIGHT : BASE)
           with 1-texel smoothstep (width 0.02) between bands (crisp, no gradient)
T_shade  = 0.42   // ≈ lower-right third of a convex form is in shade, like cel()'s band
T_light  = 0.86   // narrow warm crescent on the lit rim
colour   = toneColour(base, band, shadowAmt, lightAmt)  // formulas above, computed IN SHADER (sRGB space)
         + rim (§1.4) + emissive + feedback overlays (§1.8)
```
Because `shade`/`light`/`line` are pure functions of the base colour and two scalars, assets only store **base colour
+ (shadowAmt, lightAmt)** per material region. Use a **palette texture** (§1.7): `T_AF_Palette_BC` (base colour swatches)
plus `T_AF_Palette_P` (R = shadowAmt, G = lightAmt, B = emissive strength, A = outline-colour mix) sampled with the same
UV. Default `(shadowAmt, lightAmt) = (0.42, 0.32)`; per-material overrides are listed in every palette table below as
`(s, l)`.

**render-only (2D artefacts not to port):** "far" tones (e.g. `STEEL_FAR`, `ROBE_FAR`, `skinFar`) are darker copies the
2D drawer uses for limbs on the far side of the body (`PlayerWarrior.ts:57-60`, `Townsfolk.ts:138-143` `farTone = rgb×0.7`).
In 3D the lighting does this; **do not** model separate far-side materials — except where a "far" tone is also used as
a distinct material region (called out per asset, e.g. mage mantle = `ROBE_FAR`).

### 1.3 Outlines and line art

Web characters get a **solid ink silhouette** stamped around the sprite (8 directions) in `#120C18`, width 1.1 rig
units (`Rig.ts:432-447`); legacy/decor art uses coloured strokes 0.5–0.9 px (`DecorKit.ts`); icons `#140C1C` 2 units in
96 (`src/graphics/icons/IconKit.ts:368-403`); ground has none (`src/graphics/terrain/TerrainStyles.ts:1-6`).

3D: **inverted-hull outline** (second material slot / `M_AF_Outline`, front-face culled, vertex extrusion along smoothed
normals **in clip space** so thickness is constant on screen) + painted interior crease lines in the base-colour texture
(seams, plate edges, stitching — the web strokes them with the `line` tone).

| Category | Outline colour | Screen width at 1080p (scale ∝ viewport height) | Interior lines |
|---|---|---|---|
| Heroes | ink `#120C18` | **3.5 px** (web: 1.1 unit × 1.18 ≈ 1.9 % of hero height) | `line` tone, 1.5 px |
| Monsters | ink `#120C18` (slime: ink too; ghostly monsters later may override) | 3.0 px (bosses 3.5) | `line` tone |
| NPCs | ink `#120C18` | 3.0 px | `line` tone |
| Interactive props (chest, portal, lore, loot bag, potions, hearthstone, puzzle pillar) | the prop's `line` tone (softer ink) | 2.0 px | yes |
| Decorations (trees, bushes, rocks, camp props, ruins) | the material's `line` tone | 1.2 px (none on grass/flower ground cover) | sparse |
| Ground / water | none | 0 | none |
| VFX | none (soft additive) — except "inked" bolts/claws that draw a dark under-stroke (`FxKit.ts:279-301`, `SkillEffectSystem.ts:170-181`) | — | — |

Mobile fallback: if the inverted hull is too costly, a post-process Sobel on scene depth + custom-stencil category
(stencil 1 hero, 2 monster, 3 NPC, 4 interactive) with the same widths. Hull is preferred (works with MSAA, no
post-process pass).

### 1.7 Texturing strategy (procedural, mobile-friendly)

* **Palette atlas** (default for every mesh generated by Blender Python): UV islands collapsed onto 16×16-px swatches of
  `T_AF_Palette_BC` (256², 256 swatches; sRGB) + `T_AF_Palette_P` (linear, see §1.2). One palette per family
  (`Heroes`, `Monsters_Plains`, `NPC`, `Props_Plains`, `Foliage_Plains`). Swatch indices are assigned by the Blender
  scripts from the hex tables in this spec (export `tone_presets.json`, §11).
* **Detail decals** only where shapes are too small for geometry: emblems (warrior shield flame, chest ember sigil),
  faces (eyes, mouths, war paint), runes, stitches — `T_<Asset>_Detail` 512² RGBA (alpha-blended in the same material
  via a second UV set). Never noise.
* **Emissive** via palette param B (bloom picks it up; desktop bloom per `world-map-nav.md` §14.1).
* Texture budgets: palettes 256²; detail decals ≤ 512² (heroes 1024² allowed for face+emblem sheet); ASTC 6×6 on mobile.

## 2. Pipeline conventions

### 2.1 Directory layout

| Path | Content |
|---|---|
| `unreal/Art/Blender/scripts/` | Python generators (one module per family: `heroes.py`, `monsters_goblin.py`, `slime.py`, `npc_kit.py`, `props_camp.py`, `foliage_plains.py`, `fx_meshes.py`, `icons.py`) reading the JSON tables of §11 |
| `unreal/Art/Blender/source/<Family>/` | generated `.blend` files (never hand-edited; regenerated) |
| `unreal/Art/Export/<Family>/` | FBX + PNG outputs, names exactly as the UE assets (§2.2) |
| `unreal/Content/Abyssfire/` | UE assets: `Characters/{Heroes,Monsters,NPCs}`, `Environment/{Plains,Common}`, `Props`, `FX`, `UI/Icons`, `Materials` |

### 2.2 Naming conventions

Asset prefixes (UE): `SK_` skeletal mesh · `SKEL_` skeleton · `PHYS_` physics asset · `A_` anim sequence · `AM_` montage ·
`BS_` blend space · `ABP_` anim blueprint · `SM_` static mesh · `M_` material · `MI_` material instance · `MF_` function ·
`DM_` decal material · `T_` texture · `NS_` Niagara system · `NE_` Niagara emitter · `CS_` camera shake · `DA_` data asset ·
`WBP_` widget · `LS_` level sequence.

Pattern: `<Prefix>_<Category>_<Name>[_<Variant>][_<Suffix>]` — PascalCase tokens, no spaces, ASCII only. Exception:
assets generated 1:1 from data ids (item/skill/quest-item icons, glyphs) keep the **web id verbatim** after the prefix
(e.g. `T_UI_ItemIcon_w_sword__w_broad_sword` ≡ web `item_icon_w_sword__w_broad_sword`) so the mapping stays mechanical.

| Category token | Used for | Examples |
|---|---|---|
| `Hero` | player classes | `SK_Hero_Warrior`, `SM_Hero_Warrior_Sword`, `A_Hero_Warrior_Attack01` |
| `Mon` | monsters | `SK_Mon_Goblin`, `SK_Mon_GoblinChief`, `SK_Mon_Slime`, `A_Mon_Goblin_Walk` |
| `NPC` | townsfolk (merged looks) and kit parts | `SK_NPC_Blacksmith`, `SK_NPCKit_Body_Stout`, `SK_NPCKit_Hat_WideBrim`, `SM_NPCKit_Prop_Hammer` |
| `Prop` | interactive / camp / story / lore props | `SM_Prop_Camp_Tent`, `SM_Prop_Story_ElvenRuins`, `SM_Prop_Lore_AncientTablet`, `SK_Prop_TreasureChest` |
| `Foliage` | trees, bushes, grass, flowers | `SM_Foliage_Plains_Oak_A`, `SM_Foliage_Plains_GrassTuft_B` |
| `Rock` | rocks, boulders | `SM_Rock_Plains_Cluster_A`, `SM_Rock_Plains_MossBoulder_A` |
| `Outcrop` / `Palisade` | wall-tile and camp-wall meshes | `SM_Outcrop_Plains_V0..V5`, `SM_Palisade_Plains_Stake_A`, `SM_Palisade_Plains_GatePost` |
| `Loot` / `Pickup` | ground loot | `SM_Loot_Bag`, `SM_Pickup_PotionHP`, `SM_Pickup_GoldCoin` |
| `FX` | VFX meshes, textures, systems | `SM_FX_Arrow`, `SM_FX_HexPlate`, `T_FX_Glow`, `NS_Skill_Fireball`, `NS_Hit_Impact` |
| `UI` | icons and portraits | `T_UI_ItemIcon_w_sword__w_broad_sword`, `T_UI_SkillIcon_fireball`, `T_UI_Portrait_QuestElder` |

Texture suffixes: `_BC` base colour (sRGB), `_P` palette params (linear), `_N` normal (rare), `_E` emissive mask,
`_M` mask (R ao/grounding, G emissive, B tint mask), `_Detail` decal sheet, `_Flip` flipbook (with `_<cols>x<rows>`).

**FBX files** (Blender export, one asset per file, file name = UE asset name):
* Skeletal mesh: `SK_<…>.fbx` — armature + mesh in bind pose, **no animation**.
* Animation: `A_<Family>_<Name>_<Action>.fbx` — armature only (no mesh), one action per file, frame range = clip.
  Action tokens (fixed vocabulary): `Idle`, `Walk`, `Run`, `Attack01` (`Attack02`…), `Cast01`, `Hurt`, `HurtAdd`,
  `Dodge`, `Death`, `Stun` (NEW), `Spawn` (NEW), and NPC actions `Work_<Style>`, `Alert`, `Talk`, `IdleNPC`, `Turn90L/R`.
* Static mesh: `SM_<…>.fbx`; collision hulls `UCX_<SMName>_00..`; sockets `SOCKET_<name>` (UE strips the prefix);
  LODs as `<SMName>_LOD1` objects in a `LODGroup` empty.
* Icons/portraits: `T_UI_<…>.png` (RGBA, straight alpha).

Web key → UE asset mapping is exported as `art_manifest.json` (§11) so the core's data tables keep their web ids
(`spriteKey: "monster_goblin"`) and the UE module resolves the asset path.

### 2.3 Blender scene and export settings

* Units: Metric, Unit Scale 1.0, **1 BU = 1 m = 1 tile**. Export FBX with `apply_unit_scale=True`,
  `apply_scale_options='FBX_SCALE_ALL'`, `global_scale=1.0` → 1 m = 100 uu.
* Orientation: characters and directional props **face Blender −Y**, +Z up. Export `axis_forward='-Z'`, `axis_up='Y'`
  (Blender defaults); UE import with *Force Front X Axis* off → assets face **+Y** in UE (mannequin convention); the
  character mesh component is rotated yaw −90° in the actor.
* Pivots: characters at the ground point between the feet (root bone at origin); static props at the centre of their
  ground footprint, Z = 0 at the ground contact (so placement = tile centre + jitter, `world-map-nav.md` §15.5);
  wall/palisade pieces at the tile centre.
* Armature export: `add_leaf_bones=False`, `use_armature_deform_only=True`, `bake_anim_use_nla_strips=False`,
  `bake_anim_use_all_actions=False` (one action per file), `bake_anim_simplify_factor=0` (keep authored keys),
  `primary_bone_axis='Y'`, `secondary_bone_axis='X'`.
* Smoothing: export "Face" smoothing; outline hull uses a **custom smoothed-normal set** baked into vertex colours
  (RGB = averaged normal) so hard edges do not split the outline.
* Root motion: **none** (all clips in place; the core moves actors). Dodge/lunge displacement is visual-only (§2.5).

### 2.5 Animation authoring rules

* **In place**, 60 fps, loops (`Idle`, `Walk`, `Run`, NPC loops) start and end on the same pose (web loops sample
  `t = frame / count`, one-shots `t = frame / (count − 1)`, `Rig.ts:546-549`).
* **Notifies** (names fixed, read by the UE module): `Contact` (attack blow), `Release` (cast), `FootL`, `FootR`
  (dust puffs/SFX), `FX_<Name>` (e.g. `FX_HammerStrike`, `FX_SpiritBolt`), `WindupEnd` (telegraph end, monsters).
* **Play rate**: attacks play at `1 / speed` where `speed = clamp(intervalMs × 0.9 / attackDurationMs, 0.35, 1)`;
  casts are **not** scaled; locomotion play rate = `groundSpeed / refSpeed` of the clip (§10).
* **Blend times** (ms, from `CharacterAnimator.ts:306-328`; author clips so these blends look clean):
  idle→walk 90, walk→idle 110, idle→attack 45, walk→attack 55, attack→idle 75, attack→walk 70, idle→cast 65,
  walk→cast 70, attack→cast 55, cast→attack 55, cast→idle 85, cast→walk 75, idle→dodge 35, walk→dodge 30,
  attack→dodge 25, cast→dodge 25, hurt→dodge 40, dodge→idle 65, dodge→walk 55, hurt→idle 105, hurt→walk 90, default 80.
* **Hit-stop** freezes only that actor's animation (`combat-feel.md` §11.2) — clips need no special handling.
* **Dodge**: the core repositions the hero instantly (`combat-feel.md` §8.1); the UE module lerps a *mesh offset* from
  the old to the new position over the dodge duration, so dodge clips are authored in place.
* **Facing**: the web draws two baked views (front 3/4 `se`, back 3/4 `ne`) and mirrors them (`types.ts:56-63`,
  `CharacterAnimator.ts:75-90`) — **render-only**; in 3D the actor yaws toward its velocity/target (suggest 720°/s,
  small dead-band). Clips are authored facing forward only.
* **View-specific pose tweaks are render-only**: e.g. the warrior's sword hangs down in the back view
  (`PlayerWarrior.ts:739-750`), the mage swings the staff out to the side in the front-view cast so it does not cross
  the face (`PlayerMage.ts:653-667`). In 3D author the true 3D motion (sword at the side when idle-walking away is a
  real pose choice, not needed).

## 4. Monsters (Chapter 1)

General rules (all monsters, `src/graphics/sprites/rig/MonsterKit.ts`):
* Web sheets: idle 4 frames @ 6 fps (loop 667 ms) · walk 6 @ 10 (loop 600 ms) · attack 4 @ 12 (**contact on the last
  frame = 250 ms**, then a tweened recovery to 500 ms) · hurt 2 @ 10 (200 ms) · death 4 @ 6 (motion 500 ms, 667 ms

  cast or dodge** action.
* Humanoid monsters derive attack/hurt/death from a READY pose + an attack style (`humanoidTracks`, `MonsterKit.ts:142-218`):

* Telegraph tint during the first 155 ms of the attack (`#FFC4B0` / elite `#FF7A5C`) — material param (§1.8).
* Monster facing: heading while moving, the hero while attacking; humanoid monster heads turn toward the camera in the

* Elites: crown above the head (§4.6), orange name label, affix auras (§8.7).

**lily pads** (instanced flat meshes `SM_Foliage_Plains_LilyPad_A/B`, ≈ 25–35 cm) and optional grass "bigTuft" cards.
Ground has **no outline**, two tones per material, low contrast (§1.5).

**Transitions** (exact web algorithm, `ZoneTerrain.ts:330-405` — implement as `MF_TileBlend` in the material): each
pixel looks at the 4 tiles around its tile corner; weight `w = (1 − d²)²` for `d² < 1` (d = distance in tiles to that
tile's centre), normalised; score per material `s = w_norm + rank × 0.025 + 0.3 × noise_m(uv)` (noise = a periodic
value-noise texture per material, period 3 tiles); winner `t1`, runner-up `t2`, `Δ = s1 − s2`; coverage
`α = 1 if Δ ≥ 0.025 else 0.5 + Δ/0.05` (crisp anti-aliased cel edge). Edge tints:
* `t1` liquid (water side): shallow tint `(1 − smoothstep(0.5, 0.95, w1)) × 0.75` toward `#6CC3CF`; **foam** `#EEF9F2`
  where `Δ < 0.065` with strength `(1 − Δ/0.065)^0.6 × 0.92`.
* `t2` liquid (land side of a shore): **bank** `#8C7448` at `0.7 × (1 − Δ/0.045)` for `Δ < 0.045`, then
  `0.25 × (1 − (Δ − 0.045)/0.055)` up to `Δ < 0.1`.
* higher-ranked material on top (`rank1 > rank2`): cel **lip** highlight (style `lip`, else base mixed 25 % toward
  `#FFF2D6`) at 0.75 strength for `Δ < 0.032` → grass laps over paths with a bright rim.
* lower-ranked on top (`rank1 < rank2`): dark edge `#241A3A` at `0.2 × (1 − Δ/0.055)` for `Δ < 0.055`.

**Water** (`world-map-nav.md` §15.1: basin, surface Z −12 cm, bed ≈ −60 cm, bank slope over the outer 0.3 tile):
`M_Water_Plains` — opaque-looking toon water: base `#3F93B8`, depth-fade to `#6CC3CF` in the shallows, animated foam band
`#EEF9F2` (≈ 8 cm) on the shoreline, slow-scrolling wave flecks `#A9E2EE` α 0.7, no reflections; lily pads on ≈ 1 in 6
water tiles. Emerald Plains has two lakes in the south (67 and 296 tiles, `world-map-nav.md` §3.3).

## 8. VFX

### 8.1 Conventions (web FX engine → Niagara)

Web: a pooled particle engine (`src/graphics/vfx/FxEngine.ts`, cap **900** live particles) with composite helpers
(`FxKit.ts`) and painted textures (`FxTextures.ts`). Particle model (`FxEngine.ts:13-60,120-260`):
* default blend **additive**; `.normal()` = alpha-blended and depth-sorted with the world (smoke, debris, solid slash
  bodies, flame tongues, hex plates, shards, blood/venom drops);
* scale over life `s(t) = s0 + (s1 − s0)·(1 − (1 − t)^pow)` (ease-out power), separate X/Y;
* alpha: linear fade-in to `a0` over the first `fadeIn` fraction, then `a0 → a1` with `u^pow` (ease-in);
* velocity + acceleration (px/s, px/s²), drag `v *= e^(−drag·dt)`, optional velocity-aligned stretch, spin;
* orbit mode (iso-flattened circle around a point with angular & radial velocity);
* `wait(ms)` start delay; `flicker(k)` multiplies alpha by `1 − k·rand` per frame.

3D mapping: every web "effect" becomes a **Niagara system** `NS_<Group>_<Name>` composed of the primitive emitters of
§8.3 (user parameters: colour, radius, count, lifetime, delay). Ground-plane helpers (`ring`, `shock`, `decal`,
`swipe`) become true horizontal circles/decals (iso squash `FLAT = 0.5` is render-only). Heights: the web measures
from the feet in screen px — use sockets instead: `CH = 18 px` "chest" → `fx_chest`; launch points `cy − 22` →
`fx_hand_r` / staff `crystal`; `ty − 52` → `fx_overhead`; ground `gy` → Z 0. Sizes/speeds per §0.1 (`TILE_R = 45 px`
= 1 tile for AoE radii). Projectile flight time is **dictated by the core** (`combat-feel.md` §6.4, web
`getProjectileTravelMs`, `SkillEffectSystem.ts:38-49`); the Niagara head is driven to arrive exactly then.
Particle textures are white/greyscale and tinted (a few are pre-coloured, §8.4).
Camera shakes listed per effect are owned by `combat-feel.md` §11.5 (`CS_` assets); they are repeated here only for
completeness.

The UI kit itself (panels, frames, buttons, fonts, `UI_COLORS`) is owned by `save-ui-input.md` §8. This section owns the
**icons** and **portraits**. All icons share the web icon language (`src/graphics/icons/IconKit.ts:1-8,368-420`):
authored in a 96-unit square, cel-shaded with coloured line art, light from the upper-left, rim light
`rgba(255,240,210,0.45)` 1.1 u wide on the upper-left edge, a dark **ink silhouette `#140C1C` 2 u wide** (2.1 for skill
motifs, 3.6 for quest markers), transparent background, one focal accent (sparkle/glow). **Quality framing is the
caller's job** (slot border colour/glow), never baked into item icons (`ItemIcons.ts:1-17`).

Generation (recommended): **Blender renders** — orthographic camera, the item/motif modelled in 3D with `M_AF_Toon` +
outline, key light upper-left, rendered to 256² RGBA (web icons are 96² displayed at 36–48 px; skills 128²; glyphs
64²), then the same ink/rim post-pass as the web (`inked()`) in the compositor. Item icons rendered from the **same
meshes** as the optional equipment visuals (§3.6). Output `T_UI_ItemIcon_<iconId>[__<baseId>]`,
`T_UI_SkillIcon_<skillId>`, `T_UI_QuestItem_<kind>`, `T_UI_Glyph_<id>` (names mirror the web keys
`item_icon_<id>[__<variant>]`, `skill_icon_<id>`, `quest_icon_<kind>`, `glyph_<id>` so the mapping is mechanical).
